# Documentation Guide

I kept the final project documentation separate from the historical planning
and AI collaboration records.

## Start here

- `../README.md` - product overview, local setup, deployment, and testing
- `SUBMISSION_CHECKLIST.md` - assessment coverage and production demo
- `ARCHITECTURE.md` - system design and request flows
- `SECURITY_AND_RELIABILITY.md` - threat model, idempotency, and retries
- `DATA_MODEL.md` - tables, constraints, and ownership
- `DECISIONS.md` - final architecture decisions and trade-offs
- `SUPABASE_SCHEDULER.md` - production worker setup and verification
- `../AI_NOTES.md` - required AI collaboration summary

## Historical records

- `plans/` contains the implementation plan for each completed piece of work.
- `IMPLEMENTATION_ROADMAP.md` records the original 72-hour build sequence.
- `LEARNING_LOG.md` records concepts and problems encountered during the build.
- `../AI_WORK_LOG.md` is the chronological AI collaboration record required by
  the repository instructions.
- `../README_STARTER.md`, `PROMPT_LIBRARY.md`,
  `AI_COLLABORATION_GUIDE.md`, `AI_NOTES_EXAMPLE_STRUCTURE.md`, and
  `CODEX_START_PROMPT.md` are preserved because they were part of the context
  used during development. They are not descriptions of the final system.

The supplied assessment itself is preserved unchanged in
`../Assessment Requirement Doc.pdf`. `ASSESSMENT_BRIEF.md` is only a working
Markdown summary.
